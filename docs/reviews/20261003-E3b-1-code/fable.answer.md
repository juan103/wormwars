## Verdict: fix then start

The implementation follows the pre-registration in nearly every place I checked, and the registered arithmetic (mask, GA, reads, blocks, statistics, cuts) is right. Four things need fixing before a formal stage runs. Three are in §5/§10's failure and admission paths, one is a composition misstatement in the champions stage.

### Blocking

**B1. A kill during in-stage attempt 2 or 3 leaves the stage unrecoverable.** `scripts/e3b1.py:647-649`. §5 says a crash or kill after the second attempt makes the stage final with its runs "failed", which needs a final record. The path: attempt 1 ends non-finite, attempt 2 is killed (marker, no record). The next `--rerun` runs `rerun_plan` first (`scripts/e2.py:586`, reconciling the kill), then `requires`, which sees `attempts_final` true and raises SystemExit before any record or marker is written. `stage_state` stays "killed", so `check_order` and `trained_records` refuse every later stage forever. The same happens after two non-finite attempts and a killed third. Test 4 covers the crash case (`test_a_crash_propagates...`) but not the kill. Fix: let the rerun through and let `train_attempts` return final, so the frame writes the stopped record with `final: true` via salvage, or write the final record in `requires` before exiting. Add the kill test.

**B2. In-stage admission ignores the running stage's hours.** `scripts/e3b1.py:688`. `admit` calls `spent_hours()` with no start time. The clock reads `compute.json`, which only holds finished processes' attempt files, so an attempt 2 after a non-finite attempt 1 is admitted without charging attempt 1's hours, which can be a full training stage. §5 and §10 say every attempt is admitted like its stage, on hours spent. The cap itself is safe because `CapClock.check` adds the process's elapsed time, but the admission formula does not. Fix: `spent_hours(ctx.cap.t_start)`.

**B3. An in-stage refusal does not stop later training stages.** `scripts/e3b1.py:620-624` and `690-692`. When attempt 2 is not admitted, no `*-refused.json` is written. The frame records the stage as stopped and final, `stage_state` returns "final-stopped", and `check_order` lets the next training stage start under its own, smaller projection. §10: "Once one is refused, no later training stage starts." Fix: write `refused_path(stage)` on `not_admitted`, which also makes `trained_records`' "absent after refused" logic apply.

**B4. Champion validation runs in chunks of 4 strains, and the record says 32.** `scripts/e3b1.py:752` calls `rollout` without `chunk_worlds`. The default is 512 worlds (`wormwars/config.py:263`), and nothing in E1's config, `shuttle_config` or `maze_config` changes it, so each read point plays 8 chunks of 4 × 128. The champions record states composition [32, 128, 8] (`scripts/e3b1.py:789-790`). Every other formal script in the repo passes `chunk_worlds` explicitly. The pre-registration fixes no validation composition, so either is admissible, but rule 6 and §6 require the record to state the true one, and the choice can change a champion by floating-point order (D082, D091). The `project` timing at line 479 chunks the same way, so the hours are consistent. Fix: pass `chunk_worlds=pop.n_strains * len(ids("validation"))` in both places, or record [4, 128, 8].

### Non-blocking

- **A non-finite validation count names no run.** `wormwars/e04a/evolve.py:185-186` raises without `runs`, so the attempts entry has `runs: []` and attempt 3 repeats attempt 2 unchanged. §12 test 4 wants the run named. `v.score[i]` is per run, so naming is a three-line change.
- **The hook leg does not test what §5 names.** `scripts/e3b1.py:532-550` compares hook-off against hook-on in the same code, not against the engine before the change. The GPU leg against `train-ga.json` does cover the code change. The record's `identical: true` should say what was compared, or it overclaims.
- **Admission after failed runs uses the full-plan projections.** `scripts/e3b1.py:325-327` takes `proj["champions"]` and `proj["evaluate"]` from the project record. §9 says they are recomputed over completed runs after failures. Conservative, so it can only refuse a stage §10 would admit.
- **The evaluate record states nominal compositions only.** `scripts/e3b1.py:1031-1033`. Block 1 has 17 organisms, so its second chunk is 1 × 256, and the replay block splits 8 + 8 + 1. §6 says every record states the composition. Saving the plan with each chunk's size fixes it.
- **S-trail and S-peer carry the gate's labels.** `scripts/e3b1.py:1140, 1153` report "better"/"worse"/"unclear" and a lower bound computed for the "greater" direction. For S-peer (alternative "less") the bound is meaningless, and §7's wording is "increased trail dependence". Only `p` enters Holm, so no reading changes.
- **The "W2 alone" ruling.** E3b-0's +1.09 was the seed against the scripted `MC.w2_alone` under "none" (`scripts/e3b0.py:953, 967`; `RESULTS.md:22`). E3b-1's descriptor is seed minus the carrier variant, both under shared. §6 says "W2 alone on the carrier", so the code follows the text, but the results must not present this multiple as comparable to E3b-0's figure, and §8's "about E's whole contribution over the blind W2" refers to a different number.
- **Cap-stop wording.** Salvage labels runs `failed_runs` where §5 says "not run".
- **Final-stopped records skip the committed check.** `trained_records` reads them raw, without `require_committed` or `require_same_code`.
- **The smoke is weaker than it looks.** All smoke champions equal the seed (every d is 0.0 and every replay coefficient is identical), so the smoke never plays distinct organisms in one chunk or non-trivial readings. The unit tests do.
