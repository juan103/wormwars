**Verdict: bind and run, after small fixes.** The registration's logic is sound and the code implements it. Nothing I found would mislead G1, S1, G2 or P's verdicts. Three gaps need closing before binding because they touch PILOT.md's text or a registered rule: the calibration-failure path, the gate's determinism, and a handful of "reported" items that the code never computes or persists. None changes the design.

## Findings

1. **Medium. "A failed calibration takes the next graph seed" is not implemented.** `calibrate_in_world` raises `RuntimeError` on non-convergence (`wormwars/calibration.py:256`), and `scripts/e03h.py:261` calls it with no handler, so S1 would fail outright. `_graphs` (`scripts/e03h.py:216`) also fixes the set of three graphs before any calibration runs, and P rebuilds from `_graphs(con)` again at line 324 rather than from S1's recorded seeds, so a replacement seed in S1 would give P a `KeyError`. 03 and 03r saw zero calibration failures, so this is unlikely to fire, but a registered rule should not need a mid-pilot code change. Fix: make `_graphs` a generator over seeds, catch the error in S1, record the exclusion, and have P rebuild from `s1["graphs"]` seeds. Add a test with a monkeypatched failing calibration.

2. **Medium. The gate does not run inside `replay_mode()`; S1 and P do.** `_gate` (`scripts/e03h.py:189-203`) calls `tune_families` and `check_scores` in CUDA's default mode. Grid splatting is nondeterministic there, so G1's record is not reproducible, and behaviourally identical grid points (every `threshold` above the maximum food current is the same policy) can tie-break differently between runs. G2 then re-tunes K and Graded under level (`scripts/e03h.py:293`), so its memoryless family can differ from G1's in parameters, which would look like a discrepancy in the records. The verdicts are intervals over 256 paired worlds, so validity is not at stake. Fix: wrap `_gate` in `mode()`, and have G2 read G1's K, Graded and memoryless from the record instead of re-tuning. That also matches the cost table, which has G2 cheaper than a re-tune would be.

3. **Low-medium. Registered "reported" items are missing, and the per-genome arrays are discarded.** PILOT.md §2 promises grid-edge flags (02's `_edges`): nothing in `wormwars/e03h/` or `scripts/e03h.py` computes them. §5.2 promises the top-against-bottom quartile difference: not computed. DESIGN §3 promises realised sham occupancy and transitions per condition: `_rollout_scores` (`scripts/e03h.py:299-301`) keeps only `.score`. And `stage_pilot` returns summaries only (`scripts/e03h.py:386-393`), so H, S, H_dir, the selection and test scores, the selected deciles and the turn responses are gone when the process ends. Under rule 5 none of the missing items can be regenerated without a rerun. Fix: save an `.npz` of the per-graph arrays with its hash in the record, as S1 does for level, and add the three items. Cheap.

4. **Low. The projection's stop contradicts DESIGN §8's cut order.** `_projection` (`scripts/e03h.py:404`) sizes the test bank at 64 worlds and PILOT.md §5.5 stops if that does not fit, while DESIGN.md:363 says to cut W_t to 32 before anything else. Projected hours are about 2.2 against a 6-hour cap, so this is unlikely to bind, but the registration should say which rule governs. Separately: the CUDA preflight's pilot record reports 6.9 hours and "stop: redesign". That is an artefact of extrapolating from 32 genomes × 3 worlds, where fixed overheads dominate the per-episode time. The real P's compositions match the formal run, so its projection is meaningful. Worth a sentence in the record's note.

5. **Low. One seed is unregistered.** `b_readings` uses `boot_seed + 1` = 3 623 001 (`scripts/e03h.py:374`). PILOT.md §5.3 and §7 list only 3 623 000. Add it.

6. **Low. Slow memory is tuned over T alone.** `gate.py:66` fixes `fall_threshold` and `fall_turn` at M's optimum. DESIGN §4 (lines 139-141) reads as T jointly with the threshold grid. Tuning T × FALL_GRID at M's speed and turn parameters costs 45 points, about 2 900 episodes, which is negligible against the 145 000 I count for G1. The current choice weakens the slow-memory family, which makes the relief criterion easier to pass. Either widen the grid or state the restriction in PILOT.md §2. Also state that when the memory family falls back to memoryless, the memory + bit base is M's optimum (`gate.py:69-70`), since PILOT.md's "the memory optimum's speed, turn and fall parameters" has no fall parameters in that case.

7. **Low. Genome identity between S1 and P is unverified.** P reuses S1's level scores and pairs them with H from P's regenerated genomes. The graph hash is checked (`scripts/e03h.py:331`); the genomes are not. A `sha256` of `g.flat()` recorded in S1 and checked in P costs nothing and guards the pairing.

8. **Low. Process items for binding.** PILOT.md's status line says "draft 2 ... Not bound" and will be frozen into the bound hash unless changed first. The P′ command on PILOT.md:20 omits the `--rerun --reason` the driver requires. `sha()` (`scripts/e03h.py:117`) hashes raw bytes where `reg.file_sha256` normalises line endings. No stage calls `require_pushed`, though PILOT.md §1 requires a push before any stage. The cap clock is checked only between graphs in S1 and P, never inside G1 or G2. The cost table's 0.05 h for G1 looks optimistic: 02's T1 diagnostics, with fewer points, took 206 s (`experiments/02-screening/diagnostics.json`). My estimate for everything through P′ plus step 0's 158 s is 0.4 to 0.6 h, so the 1.0 h cap holds.

## Answers to the four questions

**PILOT.md draft 2.** The family construction nests by explicit fallbacks with first-maximum ties, and the code matches it. The amplitude rule keyed on the decile shift is clear and cheap; note its interval conditions on frozen deciles and three fixed graphs, so a shift of a few thousandths can "move", which is fine for a manipulation check but should not be read as an effect size. B's readings and the reported power are as written. Seeds and world ids are disjoint from 02 (950 to 980 million), 03, 03r and 03mc (993 to 996 million), 03a (1.48 billion), E1, E3, E4 and the rule-7 check, with the one omission in finding 5.

**Code against PILOT.md and §13.** It implements them. The bit, sham, counts, decile selection, reliability estimator, partial Spearman, s_shared, power and U are all as registered. No bug misleads a verdict or the sizing.

**Test gaps.** No test of the calibration-failure path (finding 1). `shared_world_sd_of_mean_D` and `_projection` have no tests against hand values. The memory + bit fallback branch is never exercised by `FakeTune`. The driver test only checks that P′ is refused, never that it is allowed. `smoke_grids()` (`scripts/e03h.py:176`) mutates the shared gate module, so `test_the_grids_are_02s` depends on file order within one pytest process.

**`rollout`'s new output.** It changes nothing for earlier experiments. The field defaults to `None`, `_play` reads the counts only when a mode is set (`rollout.py:123`), the world's validation passes for the pinned interface without a mode, the config hash omits the unset field, and the committed rule-7 records compare class-E endpoints bitwise against the pre-03h engine on CPU and CUDA.
