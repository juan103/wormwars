**Verdict: agree, with fixes.** The design fixes are in, the code does what the plan says in every place I checked, and nothing is post hoc. Two code defects should be fixed before the run: the cap forecast will probably halt the run falsely, and the scores stage saves nothing until it finishes. The rest are wording and reporting gaps.

## What I verified

- **Exact rescaling.** `BrainConfig.dt` is a property, `1 / substeps` (`wormwars/config.py:70`). `Brain` takes `genome.cfg` (`brain.py:317`), and the world steps it without a substeps override (`world.py:998`), so setting substeps on the genome's config is the right lever. `scaled` clones, never clamps, and refuses inexact k (`step2.py:76-90`). The bitwise test at k = 0.5 and 2 is sound; 0.25 and 4 follow by the same power-of-two argument.
- **Batch composition.** `chunk_worlds` defaults to 512 and 02's task config does not change it, so 16 strains fit one chunk (`rollout.py:165-166`). Three strains per arm is genuinely one batch. `score_run` uses the 32 criticality worlds, the run's seed and the CPU, and keeps per-world scores.
- **Probe.** `probe_states(ticks=0)` returns the ramp-end state at k = 1; `follow_from` records y at the start state and after each of the 100 ticks (`pilot.py:412-416`), so `dc[0]` is the written difference and `dc[1:]` is ticks 1 to 100, as the plan says. `a_written_at_1` is the same number in every arm, as it should be.
- **Reader.** The control comparison is the champion's absolute change minus the control's, over the champion's intact score, floor on the champion only (`step2_read.py:174-177`). T1 minus T0 pairs by graph-and-run block; records.jsonl gives 24 shared blocks (N2 runs 0 to 7, SH1 to SH8 runs 0 and 1) and 30 T1 blocks with the six N2perm runs. Validation and consistency match the plan's criteria; criticality.json holds exactly the 24 T1-M0 keys. Averaging and bootstrap match.
- **Genomes.** All three T1 labels are hashed against M6-0's list, not only drift0. Counts 102 and 72 follow from the records.

## Fixes, ranked

1. **The forecast will likely stop the run falsely** (`step2.py:184-187`). It extrapolates the first three runs, all T1 and the heaviest, to all 174 records. With the plan's own timings a T1 run is about 100 s and a T0 run about 35 s, so the forecast reads about 4.9 h against the 4.25 h threshold, while the true scores total is about 3.5 h. Weight the forecast by arm load (a T1 run is 712 strain-substep units, a T0 run 248, so multiply by 102 + 72 × 248/712 ≈ 127, not 174), and add a test. The test suite does not cover the forecast.
2. **Nothing is saved until the stage ends** (`step2.py:190`, `step2.py:227`). A stop or crash at run 150 loses three hours. Dump a partial file after each run and resume from it. Compute is the project's bottleneck; this is worth ten lines.
3. **The test log is stale.** `runs/step2-tests.txt` records 9 passed, 1 failed (the `without_excess` test before `wobble` was added). The "10 pass" claim has no committed evidence. Regenerate it.
4. **A third control wording is missing** (`step2_read.py:85-90`). If the primary is a reduction and the control comparison's interval lies above zero, the control fell more than the champions, yet the output says "no detected excess over". Fix the wording now: "The reduction was smaller than that of …". Also the fallback when the primary is not a reduction is not in the plan, and the control sentences are still emitted when the reading is inconclusive (`step2_read.py:208-209`).
5. **Individual validation failures are not listed.** The plan promises them and names the switch champion, but `validation()` gives only n, median and share per arm. Add the keys with a ratio of 1 or more at k = 0.25 and the switch champion's row. The supporting measures `a_full` and `full_integral` are computed and never summarised; summarise them or say in the plan they stay in probe.json.
6. **Spearman ties** (`step2_read.py:93-98`). Ordinal ranks via `argsort().argsort()` break ties arbitrarily, and block resampling creates exact duplicates, so x and y copies can rank inconsistently in every draw. Use `scipy.stats.spearmanr` as 02b's `analyse.py:88` does. State the association's 1,000 draws in the plan; the 10,000 applies only to the means.
7. **Plan leftovers.** Say the k > 1 hazard Fable asked for (warm-up from zero lengthens in a 200-tick episode). Astra asked for the timing command and raw output to be archived; nothing in `runs/` holds them. Note that the boundary neurons in the interior arm run at 128 substeps with unchanged tau, a finer discretisation than intact, so that arm is not purely an interior speed-up (negligible at c ≤ 1/16, not worth a baseline). Note that k = 1 shares its three-strain composition with 0.25 and 4 but not with 0.5, 2 and the interior arm; the 02b check bounds that noise.

## Cuts

- **The controls' probes.** The reader uses only g39's probe; g00's and drift0's are about 45% of the probe stage and feed nothing. Cut them or name a use.
- **The probe's "about 10 minutes" is probably low.** Per T1 run it is about 224,000 single-strain substeps, likely 20 to 40 minutes overall. Not a cap risk, but time it or batch the three genomes per arm with `Genome.cat` as M6-0 did.
- T0 at k = 0.5 and 2 costs about 14 minutes and gives the slowing profile. Keep it.
