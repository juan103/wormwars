**Findings**

1. **The build has no "pushed" check.** `guards` (scripts/p4mc.py:150-153) runs `require_formal` for check and run only; for build it checks the bound text, code unchanged and a clean tree, but not that HEAD (and so the bound commit and bound.json) is on origin. §1.1 and §9.1 promise fresh graphs are drawn only after binding *and pushing*. Fix: for build, after the dirty check, fetch and require `merge-base --is-ancestor HEAD origin/<branch>` (factor `require_formal`'s push step into a `require_pushed` in registration.py and call it here). Add a test that a build with an unpushed HEAD refuses, as tests/test_registration.py:70 does for `require_formal`.

2. **The empty-deletion stop is defeated by a resume.** On failure the unit is stored, the loop breaks, and `measurements.json` is written with the unit present (p4mc.py:533-548). A second `run` skips every stored unit (526-527) and carries on past `qb/0/empty`, so the registered stop ("or the run stops", §3) is one rerun away from being bypassed, and `check_resume` (479-489) does not look at earlier outcomes. Fix: in `check_resume`, refuse if any attempt's outcome starts with "stopped: the empty", or re-evaluate `empty_reproduces` on the stored `qb/0/intact` and `qb/0/empty` records and refuse if they differ. Add it to the resume test.

3. **The report stage is unguarded and overwrites.** `cmd_report` (p4mc.py:553-564) checks nothing: not the bound text, not the code since the bound commit, and it records no provenance; `report.json` is overwritten each time; `load_arrays` (467-469) never checks the sha256 recorded per unit (531). §9 says every formal stage refuses unless the bound text and code are unchanged, and the arrays are the only local inputs the committed numbers depend on. Fix: run the text and code checks (not the GPU check) in report, write provenance and the bound commit into `report.json`, and verify each unit's array hash before loading.

4. **Q-A's "lead narrows" sentence is asserted, not computed.** mc_report.py:139-140 appends "N2's P4 lead over each ensemble narrows without gap junctions" whenever Q-A passes and the replication is distinctive. A pass means N2's ΔP4 is below almost every null graph's ΔP4, but the lead is N2 minus the ensemble *median*, and with changes correlated with intact P4 (slope −0.26, DESIGN §6) the median of the gaps-off values need not move by the median change. The code already computes `levels.ensemble_medians` (193-196) but does not use them. Design v2.2 §4 had "by [the change in the median gap, per ensemble]"; the pre-registration dropped the number. Fix before binding: gate the sentence on the computed medians (gaps-off lead < intact lead in every ensemble) and put the per-ensemble change in the sentence, in both PREREGISTRATION.md §6 and the code; test it with a synthetic case where Q-A passes and a median moves the other way.

5. **Per-question counts fall short of §6.** "Reported for every question: ... the planned, measured and valid counts." `rank_question` (mc_report.py:65-72) reports n (valid) and `invalid`, which lumps unmeasured graphs with invalid ones. `single_signal` does it right (line 38). Fix: add planned/measured/valid per ensemble to `rank_question`'s output, and the same for Q-C (planned 256, measured, valid).

6. **A fresh draw is possible without the runner.** `python scripts/exp03.py build --instance 03mc` (exp03.py:267-269, 803) draws the 640 formal graphs into `experiments/03mc-p4-confirm/` with no binding guard; only the `ensembles.json` existence check stops a second build. Fix: have `exp03.cmd_build` refuse the 03mc instance unless an environment variable set by `p4mc.cmd_build` is present, or have p4mc call the build in-process after its guards. Low likelihood, but it is exactly the class of event rule 2 is about.

7. **Unverified risk: bitwise equality of the empty deletion on CUDA.** `empty_reproduces` (p4mc.py:492-494) requires float equality of two consecutive GPU runs outside `replay_mode`, while DESIGN §5 claims no exact repeat. The brain step is `bmm` only (brain.py:478-482), and cuBLAS is normally deterministic for the same shapes on the same device in one process, so this will probably hold; but the only evidence is the CPU smoke (identical sha256 at measurements.json:744 and 753). A false stop lands after the 256 permutations and needs an amendment. Fix: in `check` (formal), run N2 intact twice at the registered composition and `qb/0/empty`'s path once, and require bitwise equality there, so a non-repeatable GPU is found before the run. About 20 s of GPU.

8. **Guard paths are untested.** `bound`, `guards`, `cmd_build`'s refusals and the push question have no test; only `prereg_append_only` is unit-tested (test_p4mc.py:76). tests/test_e4d_evo_formal_stages.py:398 shows the monkeypatch pattern for `prereg_at`. Add tests for: missing bound.json; bound commit not an ancestor; code changed since `code_commit`; an amendment via `code_commit` whose text must also survive.

9. **Ambiguities in the pre-registration** (text only):
   - "response" is never defined; say once that it is P4's denominator, the mean |steady contrast| (§3), and that Q-C's reference is the `qb/0/intact` unit.
   - §3 "Any failure stops the study" sits under the audit bullet; say it also covers the validation rules (plateau, 5 % acceptance, ceiling), which the code treats the same (p4mc.py:272-281).
   - §9 "Every formal stage refuses unless ..." then "It also needs CUDA ...": say the build is CPU and checks binding, code, clean and pushed (after fix 1), and whether report is guarded (after fix 3).
   - §5: a `check` that crashes before writing `prerun-check.json` leaves `markers/check-started.json` (p4mc.py:303) and cannot be rerun; say that this, too, is resolved by an amendment, or write the marker after the reference-hash check.
   - §6 Holm stop: a question blocked by an earlier failure though its own p met its slot reads "not its Holm threshold"; the wording is registered, so just note it is the step-down rule, not the threshold, that stopped it.
