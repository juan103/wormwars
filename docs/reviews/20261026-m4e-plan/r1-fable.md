## Findings, ranked

1. **The dose model has no treatment for a non-existent MLE** (`scripts/memory_m4/m4e_read.py:116`). When a host's U counts are nonzero in only one arm, the Poisson slope diverges. The smoke host had exactly that pattern: U_LH 1, the other U arms 0. Newton then runs β off to infinity; the outcome is either a `LinAlgError` from the singular Hessian, which aborts `read()` before `readings.json` is written at all, or NaN/huge slopes that silently poison the mean slope, its interval and W's and K's deviations. At M4d's rates, with U_LL and U_HL near the intact rate of zero, several hosts will do this. Astra asked for non-finite slopes to be specified; the plan covers only all-zero hosts. Fix: a host with switches in fewer than two U arms has no slope (reported, left out, like all-zero); check convergence and finiteness; add a test on counts `[0, 0, 0, k]`; and write the primaries before the dose model runs so it cannot take them down.

2. **Seed families overlap** (`scripts/memory_m4/m4e.py:48`). Block generators span 20261301 + 10·hd + arm, i.e. up to 20261498. The sign seeds 20261311 to 20261330 fall inside that range: host 0 draw 1's sign matrix shares its stream with the same draw's U_LL support choice. The audit seeds for hd = 0 collide with the hd = 2 block seeds and with sign seeds, and the coverage seed 20261342 equals block (h 2, d 0, U_LL). Different draw types from one PCG64 stream make the practical dependence negligible, and M4d had the same sign/block overlap, but the plan presents independent generators and the fix is free now. Move the sign, audit, bootstrap and coverage seeds above 20261500 and rerun the coverage simulation.

3. **The bitwise claim is tested within one batch composition only** (`tests/test_memory_m4e.py:142`; plan lines 131 to 134). The test runs a one-strain `continue_hold` against a one-strain `follow_from`. Production continues 8 to 128 strains in a batch and reruns one padded strain from its `pre_tail`. Rule 6 does not claim composition independence even on CPU. Add a test comparing a 3-strain `continue_hold` with a 1-strain one from the same state, or soften the sentence to "bitwise within one composition; the smoke's classes agreed both ways". The "both ways" smoke comparison is also not in any committed log. Either way the second pass is no looser than the frozen path, whose rerun is itself a single-strain rerun of a batched probe.

4. **The plan names a test that does not exist** (plan lines 222 to 223): "the default path of the changed pilot functions bitwise unchanged on the planted genomes". The M4e test only checks the signature defaults. M2's slow test exercises the planted rerun but checks radii and dtype, and `runs/pytest-m4e.txt` shows the 18 M4e tests alone. Run the M2 suite with its slow tests after the `pilot.py` change and record it, and reword.

5. **Promised outputs with no code behind them.** `blocks-summary.json` (plan line 238; M4d's came from `m4d_tables.py`, M4e has no equivalent) and the secondary "S1, S2, S3 of every block, and the per-genome eigenvalue predictor for every genome, with its AUC per arm" (plan line 203). 7. **The envelope discards a robust size sub-field** (`m4e_read.py:111`). If the main interval gives both "at least 0.001" and the exclusion while the envelope gives only "at least 0.001", the whole field becomes "unresolved (the unresolved genomes decide it)" although the first part holds on both. Report the intersection; use the unresolved label only when it is empty.
