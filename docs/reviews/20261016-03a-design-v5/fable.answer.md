## New findings

1. **The history-erase probe's calibration cannot calibrate it. Severity: high for the probe, medium for the design (it is descriptive).** `DESIGN.md:258-260`. The memory controller KTM stores one tick of level (`jitter_check.py:35-39`). Erasing its state every k ticks removes one decision in k, so at k = 10, 20, 50 KTM is almost untouched, exactly like the memoryless controller. Both calibrators would read "no effect", and the probe would have no positive control. Fix: add a slow-memory scripted family (level compared against an exponential average with time constant T in 5, 10, 20, 50 ticks, nested on KT). It calibrates the probe at the k it tests, and it directly tests the "slow comparison" explanation of §2 that the champions' jitter immunity leaves open. Scripted runs are cheap (the 1 920-point grid took 0.29 h, `compute.json`).

2. **"Steady state under the current input" is not defined operationally, and it cannot erase attractor-coded memory. Severity: medium.** `DESIGN.md:258`. τ runs up to 20 ticks (`config.py:37`), so convergence from the current state needs about 100 ticks of substeps per reset, and the network may be multistable. Running from the current state keeps the current basin, so a latch (the kind E3 built) survives the probe and "no effect" would not mean "no history". State: the number of substeps, the residual change reported, and which start the relaxation uses. I recommend relaxing from the zero initial state under the held input, which erases basin history too and has no transient. Itemise its cost in §10 (roughly ten episode-equivalents per reset at k = 10).

3. **Family 2 can pass only on complete or near-complete separation; say so. Severity: medium.** `DESIGN.md:226-230`. Holm's strictest level is 0.01, and 1/252 is the only p below it; the next levels 0.0125 and 0.0167 admit 3 and 4 splits. So a target passes only if essentially every MIP brain's AUC exceeds every NIP brain's. With a per-brain AUC null SD near 0.05-0.1, a true 0.1 AUC difference will often not separate. The design should state this power limit and that a family-2 null is not evidence against imprinting. If the owner wants a test with power, register the panel-mean MIP − NIP over the five targets as the single confirmatory contrast (one permutation of arm labels within each target) and keep the per-target contrasts descriptive. Either is honest; the present text understates how hard a pass is.

4. **"The search is told X's true numbers of partners of each kind" reads as a leak. Severity: low, but fix before registration.** `DESIGN.md:46`. §4 and §6 use "kind" for sensor, motor, pharyngeal, other. §5 (`:145`) means the three connection types. If the search were told how many sensor partners X has, the stratified null would no longer protect the primary. Say "of each connection type" at line 46.

5. **Criterion 2 lets one unlucky evolution stop the formal run. Severity: medium.** `DESIGN.md:287-289, 298`. In pilot-check each graph has one MIP brain, and 04a's shaped runs passed their gate 8 of 12 times. Criterion 2 is about the task and the graph, not that brain, yet a failed evolution fails the pilot and "a second needs the owner's word". Register one re-evolution per graph (a fresh seed) for criterion 2 only, counted in the cap, so the pilot reports task feasibility rather than seed luck.

6. **"Requires memory at the task level" overstates D303. Severity: low.** `DESIGN.md:81`. A gap between two scripted families shows that one tick of memory helps inside a six-parameter family, not that the task requires memory. §2's own last sentence (`:77-78`) says the champions may use "a memoryless strategy outside the families tried". Word line 81 as "the task rewards one-tick memory within the families tried".

7. **The stratified null needs two small specifications. Severity: low.** `DESIGN.md:185-188`. Kind × tertile gives up to 12 strata; pharyngeal (about 20 neurons) and the 39 interface neurons split into strata of a few members, where a permutation is near the identity. Report the null's mean AUC per target, so a reader sees that "enrichment" is measured over a null whose centre is not 0.5. And "one permutation ... applied to every connection type": the labels differ by type, so specify that it is one permutation of candidate identities within strata, applied to each type's labels.

8. **Criterion 1 is not a gate. Severity: low.** `DESIGN.md:285-286`. With 2.84 against 1.20 on 512 worlds (`memoryless-check.json`, SEs 0.04 and 0.05), a lower bound of 0.5 cannot fail. Keep the re-measurement as a registered number, but the 1.3 hours of re-tuning (`:324`) buy nothing; score the D303 winners on the registered check worlds instead, or spend the hours on the slow-memory family of finding 1.

9. **Small points.** `:316` lists 0.40 h with no episode count; the committed record shows 0.33 h and 2.07 M worlds, and D303 explains the other 0.07 h as deleted smoke records, so the number is not fully traceable (rule 5); say so in the table. Adding those episodes makes the total about 86.7 M, not 84 M. The no-task control runs on one MIP brain (`:252`) although it costs nothing; run it on all five.
