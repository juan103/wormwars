## Design match, piece by piece

- **The bit** (`wormwars/world.py:910`). Gain and input gain, then the clamp, then a strict `<` against the previous tick. First tick 0, per wey, masked by the sensing-time alive mask. Nothing resets the previous value. Clamp-equal readings give 0. Matches §3. The bit reads the first food_left neuron, which is the neuron `ScriptedBrain` reads, so the identity with `MemoryKinesis` holds in T1's mono sensing, where left equals right exactly.
- **The sham** (`wormwars/world.py:913`). Keyed by run seed, stream, world id, tick, swarm and wey, so a world and wey see one sequence regardless of genome, graph or batch position. The first tick draws from p01 / (p01 + p10). Transitions are 0 to 1 with p01 and 1 to 0 with p10. The latent chain runs through death and only the injection is masked. Matches §3.
- **Transition counts** (`wormwars/world.py:925`). Counted from tick 1 to tick 2 onward, so the forced-zero first tick never starts a transition. Both ends alive at sensing time. The previous mask is cloned before `_reap` mutates it in place. The code 2·before + now gives N00, N01, N10, N11. Matches §3.
- **T = 1 exactness** (`wormwars/e03h/scripted.py:55`). The comparison uses the previous average before the update, and `torch.where(T == 1, level, …)` stores the level itself. With memory on and bit off this is `MemoryKinesis` at any threshold. Matches §4.
- **BitKinesis equals MemoryKinesis at threshold 0 under relief.** Yes for live weys, by the argument above. Dead weys get different commands, which the world masks. The score-equality test on six worlds is strong end-to-end evidence, since one differing turn would diverge the trajectory.
- **The ASK cap** (`wormwars/exp03/samplers.py:292`). The extra neurons reach both count checkers and both weight caps. Legacy kinds pass an empty tuple, so their random streams are unchanged. Matches §3.
- **History** (`wormwars/exp03/measures.py:124`). Default keys and values untouched. The per-history values support H_dir as specified. Bank parameters are 03's. Matches §5.
- **Partial Spearman** (`wormwars/e03h/stats.py:11`). Average ranks, intercept, residual correlation, degenerate cases flagged as 0. Matches §6.
- **Step 0's recipe** (`scripts/e03h_step0.py:60`). Same graph builder, same brain config, same seed without +1, one device-local 256-genome draw, 03's worlds, run seed and 4 096-world chunk, stored gains, no recalibration. `Genome.random` draws only from the explicit generator, so the draw is 03's. Matches §7.2.

## Findings

1. **Medium, before the GPU run. Step 0's drop rule cannot tell a wrong recipe from 03's nondeterminism, and the design has no fallback if step 0 is dropped.** `scripts/e03h_step0.py:84` runs the verification inside `replay_mode()`, while 03 ran in default mode, where grid splatting is nondeterministic and the cuBLAS workspace setting differs. A last-bit difference anywhere in 400 ticks fails the zero-tolerance test and drops step 0 for a reason unrelated to the recipe. Step 0's own outputs, H and S, are world-free, and §7.7 uses step 0's spread as a floor for s_graph. Two cheap additions: first, verify the recipe world-free by regenerating one graph's +1 probe population and comparing `history()` raw_turn against the per-genome values committed in `pilot.json` (the `history` block of each graph record). Second, record the fitness replay in 03's default mode as well as in replay mode, each in its own process, since cuBLAS reads the workspace setting once per process. Then annotate §7.2, dated, with what step 0 does in each outcome, and what §7.7's s_graph rule uses if step 0 is dropped.

2. **Low. Rule 7's records do not name the reference engine.** `scripts/e03h_equivalence.py:96` writes the reference's local path only. The records in `development-records/` carry no commit of the worktree, no hash of the reference file, no torch or CUDA version and no GPU name. The claim "bit-equal against 6facc3d" lives only in D327's prose. Add the worktree's `rev-parse HEAD`, the npz's sha256 and the provenance dictionary to the record.

3. **Low. The ASK cap is zero only by assertion.** D326 states N2's ASK has no direct read-out edges. No test pins it. Add an assertion that `direct_readout` for ASKL and ASKR is zero on both matrices. It fixes the meaning of SH-mirror-ASK and of the reported covariate.

4. **Low. The bit read-out in `ScriptedBrain` assumes ASK carries only the bit.** `wormwars/exp02/scripted.py:53` tests the current for being above zero. That is correct in T1 because the pheromone scale is 0, and wrong in any task with pheromone. A guard in `score_policy` and the tuners, refusing a policy that needs the bit when the pheromone scale is nonzero, costs one line. The `BitKinesis` docstring should also say the identity holds under mono sensing.

5. **Low. The sham is keyed by the run seed too.** The design says per world and wey. The pilot's registration must fix one run seed for every condition, genome and graph, or the sham sequences differ across conditions.

6. **Note. The transition counts force device syncs every tick.** `wormwars/world.py:930` calls `bincount` and `.cpu()` twice per tick on every rollout with the channel on, fitness included. Accumulate on the device and move once at the end. The pilot measures timing, so this is efficiency, not correctness.

7. **Trivial.** `wormwars/e03h/__init__.py:13` duplicates the world's mode tuple. Step 0 rebuilds pilotSH101 twice. Neither matters.

## Tests, earlier behaviour, Astra's round 1

**Test gaps.** The interface test at `tests/test_e03h_food_fell.py:63` checks only the names of the pinned prefix, not its neurons and gains. Rule 7's rollout equality covers this indirectly, but a direct array comparison is cheap. The history test compares two calls of the current code, not the pre-change engine. The addition is pure Python after the computation, so the risk is small, and the equivalence script could compare `history()` across engines cheaply since both have it. The counts of the injected bit are asserted only under level, not under relief or sham. The three step-0 tests each rebuild two 20-pass SH graphs and roll out on the CPU, and should carry the `slow` marker. Rule 7's check otherwise covers what it claims: pre-change reference, both devices, all six class-E endpoints, the planned CUDA composition inside replay mode, and both the pinned interface and the variant under level.

**Earlier experiments.** I found no change in behaviour. The world's new validation and state touch no random stream and run nothing when the mode is unset. Unset fields leave `to_dict` unchanged. The pinned interface's hash payload is unchanged. `KINDS` and the legacy samplers' random consumption are unchanged, and the committed 03a hash reproduces. Old scripted policies receive the same arguments. The equivalence records confirm bit-equal T1 rollouts for the pinned interface on both devices.

**Astra's round-1 findings.** All ten are addressed in the code I read: the pre-change reference at the planned composition and all endpoints (1); the recorded replay mode (2), with my finding 1 as the remaining caveat; guarded and hashed inputs (3); the drop and proceed paths tested (4); the crafted clamp, death and per-wey sequence (5); the zero-rate refusal and the first-tick stationary test (6); command and state tests with conflicting sources (7); ties, constant covariate and non-finite refusal (9).
