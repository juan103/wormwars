# T1: throughput, profile first (plan v1, for review)

Roadmap v3, "Shared foundations":
- Profile to find the actual bottleneck, then tune chunk size, memory use and batching.
- Any implementation change gets an equivalence check against the previous engine, within a
  declared tolerance, recorded in DECISIONS.md.
- **Gate:** the next scheduled experiment fits its budget at the measured speed.
- A framework port is considered only if profiling points at the framework itself.

T0 left two inputs (D082, D083):
- **On CUDA a single-strain chunk is its own batch composition.** Its scores can differ from the
  same strain inside a larger chunk: up to 0.027 at 200 ticks, and 0.073 in the 600-tick stress
  test.
- **Padding or a guard is a T1 decision,** and the equivalence tolerance must be declared with
  that finding in hand.

## 1. What the profile shows (exploratory, 2026-09-28, RTX 5080, torch 2.12 + CUDA 13.0)

These numbers come from scratch scripts on a clean tree at `baa9c56`. T1.1 below regenerates them
from a committed script with provenance, and the committed JSON replaces them.

**The workload:**
- 02's task T1 with N2: 302 neurons, 20 weys per world, 32 brain substeps per tick, 200 ticks.
- Evolution evaluates 32 strains × 8 worlds per generation: one chunk of 256 worlds, so B = 160
  rows (worlds × weys) per strain.
- A hold-out evaluates one champion on 64 worlds: one strain, B = 1 280.

**Throughput (strain-worlds per second, a whole 200-tick rollout):**

| Batch | Strain-worlds/s |
|---|---|
| 32 strains × 8 worlds (evolution, one chunk) | 139 |
| 32 strains × 64 worlds, chunk 256 | 137 |
| same, chunk 512 (the default) | 179 |
| same, chunk 1 024 | 190 |
| same, chunk 2 048 | 170 |
| 64 strains × 8 worlds, one chunk | 172 |
| 128 strains × 8 worlds, one chunk | 191 |
| 256 strains × 8 worlds, one chunk | 170 |

**Where the time goes:**
- **The brain step is about 55-75% of a rollout.** One tick of the brain alone takes 5.2 ms at
  32 strains × B 160, against about 9.3 ms for the whole tick. At 16 strains × B 1 280 it is about
  20 ms of 27 ms.
- **`torch.bmm` is 69% of GPU time** in the profiler: two per substep, 64 per tick, each a dense
  302 × 302 matrix per strain. The kernel is cuBLAS's FP32 SIMT GEMM (`cutlass_80_simt_sgemm`),
  at about 12-16 TFLOPS.
- **Elementwise kernels** (add, mul, div, tanh) take most of the rest.
- **At evolution's batch size the CPU is the limit:** 873 ms of CPU time against 538 ms of GPU
  time for the same work, with 59 000 kernel launches in 100 ticks. That is why larger batches
  are faster, up to about 1 024 worlds.
- **Memory is not a constraint:** peak 0.7 GiB at 256 strains × 8 worlds.

**The matrices are sparse:** chemical 4.1% non-zero (3 709 synapses), gap 2.4% (1 091 junctions),
maximum in-degree 65 and 50.

## 2. Levers measured, and what each would cost

Bit-identical is the bar for anything adopted without a separate plan (§3).

| Lever | Speed | Result versus now | Proposed |
|---|---|---|---|
| **Several runs' populations in one batch** (R runs of 32 strains × 8 worlds) | ×1.23 at R = 2, ×1.36 at R = 4, ×1.22 at R = 8 | Expected bit-identical per strain: D082 found every composition of 2 or more strains exact. To be tested (T1.3). | Build only if the 04a or E2 budget needs it (T1.3) |
| **Chunk size 1 024** instead of 512 | ×1.06 for large evaluations; none for evolution | Bit-identical, if no chunk holds a single strain | No change (small gain) |
| **CUDA graph of the substep loop** | ×1.04-1.11 on the brain step | Bit-identical | Deferred: small gain for the complexity |
| **Several processes on the GPU at once** | none (1-4 processes: 139, 144, 145, 144 in total) | Bit-identical | Rejected: Windows time-slices processes |
| **One fused GEMM**, `[tanh v, v] @ [M; G]` | none | Differs at about 1e-6 per tick | Rejected |
| **Padding N to 304, 320 or 384; transposed storage** | none, or slower | Bit-identical | Rejected |
| **TF32 tensor cores** | ×1.2-1.6 on the brain step | Differs at about 1e-3 per tick | Rejected: a precision change, not an engine change |
| **cuSPARSE CSR** (block-diagonal over strains) | ×1.4-1.8 on the brain step | Differs at about 1e-6, and **differs between repeats of the same call**, even inside `replay_mode()`, which raises no error | Rejected: non-deterministic |

**The cuSPARSE finding matters beyond T1.** With the connectome's longest rows (65 non-zeros),
`torch.sparse.mm` on CUDA gave different results on repeated calls with the same inputs. A
synthetic matrix with about 12 per row was repeatable. `torch.use_deterministic_algorithms(True)`
did not flag it. No production code uses sparse matmul; `scripts/bench_brain.py`'s `SparseBrain`
is a benchmark. A test will pin that the production brain stays dense (T1.2).

**Conclusion:** the framework is not the bottleneck; the dense FP32 GEMM and kernel-launch overhead
are. No port is indicated. The only large exact lever is batching several runs together.

## 3. The equivalence contract (declared before any change)

**Class E: changes claimed to be exact.** This covers chunk size, batching runs together, and
single-strain padding (T1.2), each compared with the evaluation it claims to reproduce.
- **Tolerance zero:** every per-world score, energy, alive count and eaten value must be
  bit-identical on CUDA and on CPU.
- **The test set is T0's composition sweep:**
  - 32 random N2 genomes and 02's champions;
  - 200 ticks, and the 600-tick stress test;
  - default mode and `replay_mode()`.
- **A single mismatch fails the change.** It is not reclassified as class N after the fact.

**Class N: changes that alter floating-point results** (fused GEMMs, TF32, a different
summation order). **None is adopted in T1.** Because the dynamics are chaotic, per-world agreement
cannot be expected. If one is proposed later, it needs its own pre-declared plan:
- **Per step:** one brain tick agrees within a relative 1e-5 of the current engine, on random and
  champion genomes.
- **Per population:**
  - the mean paired per-world score difference lies inside ±0.01 (scores are fractions of
    starting energy), by a two one-sided test at 5%, over at least 32 genomes × 512 worlds;
  - the Spearman correlation of per-strain mean scores is at least 0.99;
  - the champion's rank is unchanged in a 40-generation single-island run.
- **Reported:** the share of worlds differing by more than 1e-4, as T0 did.
- A class N engine cannot reproduce any published run exactly. It is used only for new
  experiments, and it is recorded in each bundle.

## 4. The work

**T1.1 A committed profile script.**
- `scripts/t1_profile.py` re-measures §1 and §2's adopted and rejected rows, under
  `accounting.attempt`. It refuses a dirty tree, as the T0 GPU checks do.
- It writes `docs/foundations/T1_profile.json`, with provenance, the GPU name and the pinned
  versions.
- The throughput table in §1 is replaced by the file's numbers.

**T1.2 Single-strain padding (the D082 decision).**
- **The proposal:** `Brain.step` computes a single-strain batch as two copies of the strain and
  keeps the first. Every path that steps a brain is covered: rollouts, probes, coverage and
  ablations, not only `rollout`.
  - The cost is double brain compute for single-strain calls only. These are hold-outs of one
    champion, 64 worlds, a negligible share.
  - The alternative, padding in `rollout`, duplicates the world too and misses the probes.
- **It is a switch,** `BrainConfig.pad_single_strain`:
  - on by default for new work;
  - off to reproduce published single-strain evaluations (01b's and 02's champion hold-outs) on
    CUDA;
  - the T0 GPU check's historical replay sets it off explicitly;
  - CPU results are unchanged either way. A test checks that.
- **The test (class E):**
  - rerun T0's composition sweep with the switch on. Every single-strain case must now equal the
    same strain inside a larger chunk, bit for bit;
  - with the switch off, the old difference must still appear, so the test can fail.
- **What it also shows:** whether `bmm` is the only cause. If the world's `conv2d` over a different
  number of worlds also contributed, brain-level padding would not close the gap. The result is
  reported either way.
  - If it does not close the gap, the fallback is padding in `rollout`.
- **A test pins the dense brain:** `Brain.step` uses `torch.bmm` on dense matrices (the cuSPARSE
  finding).
- **Documentation:** `REPRODUCIBILITY.md` and T0.md's amendment are updated to say what the switch
  does.

**T1.3 Batching several runs (built only if needed).**
- **It is built when** 04a's or E2's budget, fitted at the single-run speed, does not fit its
  cap, or would take over twice as long as with batching. The decision and its numbers go in
  DECISIONS.md.
- **If built:**
  - **An `evolve_many` steps R runs in lockstep.** Each keeps its own seed, seed pool,
    selection and random streams. Their generation's genomes are concatenated for one rollout.
  - **The world takes a run seed per world,** not one per batch. It is used in map generation
    and in the keyed jitter noise.
  - **The test (class E):** every run's log, champions, snapshots and Dale signs are
    bit-identical to the same run alone, on CUDA and CPU, with R = 1, 2 and 4, and with unequal
    populations.
- Islands and coevolution are out of scope. Coevolution's chunking and the deferred layout issues
  stay with the coevolution work.

**T1.4 The gate.**
- **The next scheduled experiment is E1's positive control.** Its navigators are scripted, with
  no neural simulation, so it fits any budget. E1's pilot measures Task N's own throughput, and
  04a's budget is fitted to it (E1 design).
- **T1 closes when:**
  - T1.1's measurements are committed;
  - T1.2 passes its class E test;
  - the reviewers agree the §2 decisions are recorded.
- T1.3 is triggered by 04a's or E2's budget, not by T1.

## 5. Out of scope

- A framework port (§2's conclusion).
- Any change to substeps, ticks or the number of weys. These are experimental parameters, set by
  each design.
- Custom CUDA or Triton kernels. Triton is not installed on this Windows machine.
